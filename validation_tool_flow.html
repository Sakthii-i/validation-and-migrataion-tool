End-to-End Flows
A
Query Conversion (SF→DBX · BQ→DBX)
Translate SQL · run both engines · record latency · optional table check
CONVERT
▾
1
Input — paste SQL, CSV batch, or load file from Git (branch → file picker).
2
Translate — deterministic rules + model; outputs translated_sql, complexity score, cache hit.
3
Execute — run source (Snowflake needs sidebar connection) and Databricks; capture source_latency_ms / target_latency_ms.
4
Compare speed — Query Dashboard labels target as faster (green), slower (red), or same vs source.
5
Optional — shallow/deep validation on table inferred from SQL; push SQL to Git with reviewers.
‖
B
Table Validation
Source table vs Databricks table · PASS/FAIL per check
VALIDATE
▾
1
Connect — pick engine in sidebar; Snowflake: Establish Connection; BigQuery: project + service account on Run Validation.
2
Pick tables — Browse & Select · Manual Entry · Upload CSV · Config Driven (YAML/JSON).
3
Configure — Shallow = row count + schema auto. Deep = pick row/schema/numeric/hash; threshold %; WHERE filters; PKs for column diff; categorical columns if >1M rows + hash.
4
Run — normalizes results → validation_id + per-check status.
5
Review — History / Validation Dashboard / Details (schema table, numeric stats, hash diffs).
Validation Checks (Table Path)
Row Count Filtered COUNT on source vs target; optional threshold ratio.
Schema Column names + normalized types (case-sensitive option).
Numeric MIN / MAX / AVG + null counts on shared numeric columns (NUMBER, LONG, etc.).
Row Hash MD5 row signatures; categorical grouping for >1M rows; PK-based column diff on mismatches.
